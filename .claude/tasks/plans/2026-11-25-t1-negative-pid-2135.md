# PLAN — hotfix t1-negative-pid (2026-11-25)

## Root cause
lib/tests/deepseek-delegate.test.sh:252-254 run the engine's extracted trap
action (`[ "${RUNNER_PID:-0}" -gt 0 ] && kill -TERM "$RUNNER_PID" 2>/dev/null`)
inside a real bash with RUNNER_PID = "", 0, -1, then probe a sentinel. The
harness leads its own process group (perl setpgrp), which makes "" and 0 safe
(a regressed guard signals only that group). For -1 the group does not help:
`kill -TERM -1` signals every process the user may signal, so a regressed
guard turns `make test` into a session kill.

## Fix (one file + TODO line)
In lib/tests/deepseek-delegate.test.sh, block "trap handler" (lines 232-257).
Final shape of the block, in this order:

1. Block comment (replaces lines 232-234), stating only what is proven:
   edge pids (empty, 0, -1) run the trap action only inside a recorder
   where a shell function `kill` shadows the builtin; they run only after
   the action, given a pid the test owns, recorded exactly one
   `-TERM <pid>` in the shadow AND that owned pid is still alive (no real
   signal reached it). The real-signal harness runs behind the same gate.
2. Extraction kept, its count stored for the gate:
       ext="$(printf '%s' "$trapcmd" | grep -c 'kill -TERM')"
       check T1-trap-extracted "$ext" 1
   plus a liveness helper (zombie counts as dead; `kill -0` would not):
       owned_alive() { # owned_alive <pid>: alive and not a zombie
         local st; st="$(ps -o stat= -p "$1" 2>/dev/null | tr -d ' ')"
         [ -n "$st" ] && [ "${st#Z}" = "$st" ]
       }
3. One isolated runner replaces group_run (both harnesses use it):
       isolated_run() { # isolated_run <script> <dir> <pid> <action> -> stdout
         mkdir -p "$2"; rm -f "$2/sentinel" "$2/kills"
         perl -e 'use POSIX; setpgrp(0,0) or die; exec @ARGV' \
           bash "$1" "$2" "$3" "$4" 2>/dev/null
       }
   harness.sh body unchanged (it reads $1 dir, $2 pid, $3 action).
4. New recorder `$tmp/recorder.sh` (quoted heredoc, exact body):
       rec="$1/kills"
       RUNNER_PID="$2"
       kill() { printf '%s\n' "$*" >> "$rec"; }
       eval "action=$3"
       eval "$action"
       if [ -s "$rec" ]; then cat "$rec"; else echo no-kill; fi
5. Checks, exact order and names:
       sleep 30 & spid=$!
       ctl="$(isolated_run "$tmp/recorder.sh" "$tmp/r" -1 "'kill -0 \"\$RUNNER_PID\"'")"
       check T1-control-recorder "$ctl" "-0 -1"
       pos="$(isolated_run "$tmp/recorder.sh" "$tmp/r" "$spid" "$trapcmd")"
       check T1-positive-pid-recorded "$pos" "-TERM $spid"
       sleep 0.2   # let a leaked real signal land before the liveness check
       if [ "$ext" = 1 ] && [ "$ctl" = "-0 -1" ] \
         && [ "$pos" = "-TERM $spid" ] && owned_alive "$spid"; then
         check T1-empty-pid "$(isolated_run "$tmp/recorder.sh" "$tmp/r" "" "$trapcmd")" no-kill
         check T1-zero-pid "$(isolated_run "$tmp/recorder.sh" "$tmp/r" 0 "$trapcmd")" no-kill
         check T1-negative-pid "$(isolated_run "$tmp/recorder.sh" "$tmp/r" -1 "$trapcmd")" no-kill
         check T1-control-group-kill "$(isolated_run "$tmp/harness.sh" "$tmp/g" "" "'kill -TERM 0; :'")" ""
         check T1-recorded-pid-group-safe "$(isolated_run "$tmp/harness.sh" "$tmp/g" "$spid" "$trapcmd")" sentinel-alive
         wait "$spid"; check T1-recorded-pid-term "$?" 143
       else
         check T1-recorder-gate closed open
         owned_alive "$spid" && kill "$spid" 2>/dev/null
         wait "$spid" 2>/dev/null
       fi
   Why this order: the control uses signal 0, harmless even if the shadow
   were missing. The positive case runs the engine's own trap text on a pid
   the test owns (a `sleep`): if that text reached a real kill by any route
   (`command kill`, `unset -f`, an external wrapper), only the owned sleep
   is signalled and the output is not `-TERM <spid>`, so the gate stays
   closed and -1 never runs. If the text signalled both the shadow and a
   real route, the owned sleep is dead and `owned_alive` closes the gate.
   No static denylist. Not covered (accepted): a trap text whose edge-pid
   branch differs from its positive branch. The real-signal harness also
   runs only behind the gate.
6. Remove the old group_run function and the old T1 lines 251-257.
7. .claude/tasks/TODO.md line 106: change `- [ ]` to `- [x]` and append
   ` Fixed (hotfix 2026-11-25): edge pids go through a kill-shadowing
   recorder, gated on a signal-0 control and an owned-pid proof.`

Deliberate departure from the REQUEST: the REQUEST names a control
`kill -TERM -1`; the control is `kill -0 "$RUNNER_PID"` with -1, never
`-TERM`. If the shadow were ever missing, `-TERM -1` would kill every user
process; signal 0 delivers nothing. Self-check before reporting: the test
file contains no `kill -TERM -1` literal, and the control line contains
`kill -0`.

## Edge cases
- Extraction empty → `T1-trap-extracted` fails and the positive case gives
  `no-kill`, so the gate stays closed: no edge case runs.
- bash 4+ only for the suite (already the case).
- `eval "action=$3"`: $3 is the single-quoted trap text from the engine file
  under test (repo-controlled), same trust as today's `eval "trap $3 TERM"`.
