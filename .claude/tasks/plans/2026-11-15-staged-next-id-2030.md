# PLAN — staged-next-id (BDR-125 gap audit A4)

## CONTEXT
- lib/memory.sh:163 `_mem_next_id <file> <PREFIX>`: max over every heading
  level (`^#+ *PREFIX-[0-9]+`), fenced or not, + 1. Comment :164 says "a gap
  is harmless, a duplicate is not".
- lib/memory.sh:536 `_mem_check_staged <file>`: copies HEAD blob ($h) and
  staged blob ($s); on a v2 staged file runs `memory_check_file "$s" PREFIX
  "$h" "$1"` (new culprits: shape, duplicate, Index, open fence) and
  `_mem_removed_lines`. Caller: lib/memory-commit.sh:99 (rc 6 chokepoint,
  BDR-129). No ID-sequence rule today.
- TODO.md:171 (phase 4a ask): `check [--staged]` = validator "ID = max+1
  and unique".

## APPROACH
1. New helper in lib/memory.sh, next to `_mem_check_staged`:
   `_mem_check_next_ids <name> <PREFIX> <head copy> <staged copy>` → rc 2
   (stderr) on a bad new ID, rc 0 otherwise.
   - One awk over both files. ID extraction = the `_mem_next_id` regex
     (`match($0, "^#+ *" p "-[0-9]+")`, every level, fenced or not), numeric
     value of the digits.
   - HEAD: set `old[n]`, `max` = largest n (0 when the HEAD blob is empty or
     absent).
   - Staged: new = n not in `old`, deduplicated (a duplicate heading is
     already the culprit rule's job).
   - Sort new numerically (awk has no sort in POSIX: collect into an array
     indexed by n and walk n from 1 to the largest new n; IDs are small).
     Hmm: walk only from min(new) to max(new) — bounded by the staged file's
     largest ID.
   - expected = max + 1; for each new n in ascending order: n != expected →
     print `memory: <name>: new entry <PREFIX>-<n padded %03d> is not the
     next free ID <PREFIX>-<expected %03d>` and set bad; then expected =
     n + 1 when n == expected, else keep expected (report every bad one,
     the next good one would also mismatch: simpler = report the first
     mismatch only, then stop). Decision: report the first mismatch only,
     one line, rc 2.
   - The printed ID uses the heading's own digits (keep zero padding as
     written) for the bad one, `%03d` for the expected one (what `add`
     writes).
2. `_mem_check_staged`: in the v2 branch, after `memory_check_file`, add
   `_mem_check_next_ids "$1" "$(_mem_prefix "$1")" "$h" "$s" || rc=2`.
   HEAD absent → $h empty → max 0, first new entry must be 001.
3. Comment :164 → "every heading level, fenced or not: check --staged
   reads IDs the same way, so a new ID must be this max + 1; a duplicate
   is refused too" (keep the trucks_at_work / stray fence reason).
4. Usage lines :15-17: `--staged` adds "new IDs = HEAD max + 1, in order".

## EDGE CASES
- Several `add` calls staged together: new = max+1..max+k, consecutive →
  pass.
- Merge leftover duplicate (T7k): the duplicate ID is in HEAD → not new;
  the appended entry is max+1 → pass.
- A new ID already present in HEAD (reuse): not "new" by set membership;
  the duplicate culprit rule already refuses it when both are `## ` level.
  A new ID below max and absent from HEAD (fills an old gap) → refused.
- v1 staged file → skipped as today (branch only runs for v2).
- HEAD v1, staged v2 (`upgrade`): headings keep their IDs → no new IDs.
- Fenced heading-like line in a new entry body (`## BLK-999` in a code
  block): counted, like `_mem_next_id` counts it, so refused unless it is
  the next ID. Accepted: such a line would also move `add`'s next ID.
- IDs with 4+ digits: numeric compare.

## r2 (challenge r1: correctness CONCERNS(1 MAJOR), robustness SOLID (5 minor), simplicity CONCERNS(1 MAJOR)) — SUPERSEDES APPROACH, EDGE CASES and TESTS above
Landed: (a) body lines (`### BLK-n`, fenced `## BLK-n`) were read as new
entries → a valid `add` refused (correctness 1, robustness 2); (b) the
ascending walk was bounded by a file-controlled number (corr 3, rob 1);

renumbering is forbidden (rob 3); (d) no test for the reused-ID case the
request names (simp 1, corr 4); (e) T8h moved the shared fixture's HEAD
(corr 5, rob 5, simp 4); (f) rc 6 guide lacks the new cause (rob 4).

1. Rule = replay of `_mem_next_id` as it ran when `add` wrote each entry.
   New helper `_mem_check_next_ids <name> <PREFIX> <head copy> <staged
   copy>` → rc 2 + one stderr line on the first bad entry, rc 0 otherwise.
   One awk over the two files, `FILENAME == ARGV[1]` for the HEAD pass
   (memory_check_file idiom; an empty HEAD file yields no lines):
   - HEAD pass: `top` = max ID over every `^#+ *P-[0-9]+` line, every
     level, fenced or not (the `_mem_next_id` reading); `entry[n]` set for
     each unfenced `^## P-[0-9]+` heading (the `_mem_culprits` reading:
     toggle `fence` on `^```` lines).
   - Staged pass, in line order, `top` carried over from HEAD:
     a line matching `^## P-[0-9]+` outside a fence whose n is not in
     `entry` is a NEW entry: n != top + 1 → print `memory: <name>:<line>:
     new entry <P>-<n as written> is not the next free ID <P>-<top+1 as
     %03d>` and exit 2 (first bad entry only). Then, for every line
     matching `^#+ *P-[0-9]+` (fenced or not, any level, new entry heading
     included), top = max(top, n).
   - Consequence: body lines feed `top` but are never entries, so whatever
     `add` writes passes by construction; a reused ID absent from HEAD's
     `## ` set (body-only in HEAD, or a gap fill) is n <= top → refused; a
     reused ID present in HEAD's `## ` set is left to the existing
     duplicate culprit. No sort, no walk.
2. `_mem_check_staged`: in the v2 branch, after `memory_check_file`, call
   it only when the HEAD blob exists (`hrc` = 0): `[ "$hrc" = 1 ] ||
   _mem_check_next_ids "$1" "$(_mem_prefix "$1")" "$h" "$s" || rc=2`.
   A registry absent from HEAD (first commit of a populated or imported
   registry, holes allowed) skips the sequence rule; shape and duplicate
   rules still apply.
3. Comment lib/memory.sh:164 → say that check --staged replays this same
   reading (new `## ` entry = this max + 1), keep the trucks_at_work /
   stray fence reason; drop "a gap is harmless".
4. Usage lines lib/memory.sh:15-17: `--staged` also refuses a new entry
   whose ID is not the next free ID (registry already in HEAD).
5. lib/capitalize-commit.md rc 6 cause list (:79-91): add "a new entry
   whose ID is not the next free ID (stderr names the expected one: rename
   that uncommitted heading, or remove it and re-add with memory.sh add)".
   Keep the paragraph's wrapping style.
