# Feat plan: advisor usage section in /memory-feedback (Run C, TODO:18)

## Why
LRN-295 measured advisor use by hand (per caller, model, uncached input) and named Run C to
automate it. User choices 2026-11-19 [gated]: a section of FEEDBACK.md written by `reader.ts
apply`; sub-agents per agent type; all projects summed, no repo in the table; window = since
the last run; a retention note when the window exceeds 7 days; a shape-drift line in place of
a false zero.

## Disposition
- honors LRN-295 (the method), with one correction: a call = one served advisor iteration, i.e.
  one `message.usage.iterations[]` entry with `type == "advisor_message"` (model from that entry's
  `model`, tokens = its `input_tokens`). A `server_tool_use` block named `advisor` with no
  iteration is NOT a call: on real transcripts 147 blocks vs 141 iterations; the 6 gaps are
  requests that never ran (re-issued next message) or an `advisor_tool_result_error`. Usage rows
  repeat once per content block → dedupe by `message.id`.
- probe 2026-11-19 over all 1095 transcripts (136 calls then): 0 advisor iterations with
  cache_read/cache_creation tokens, so `input_tokens` is the whole input; rows sharing an id
  always carry identical advisor iterations, so first-seen is exact; no `isSidechain` row in a
  main transcript; no advisor row outside the two path shapes; every meta `agentType` today is a
  global or built-in agent name (general-purpose, plan-challenger, verifier, …).
- honors LRN-267: only `type == "assistant"` records count (blob replays and tool results never
  do); sub-agent transcripts = `<session>/subagents/agent-<id>.jsonl`, meta beside it
  (`agent-<id>.meta.json`, field `agentType`).
- honors BDR-140: FEEDBACK.md stays local (~/.claude/memory-feedback, never git); the section
  adds no repo name, slug, path or prompt text: callers are validated agent type strings or two
  fixed labels, models validated id strings. A project-scoped agent's own name would appear
  verbatim (none exists today).
- honors BDR-100: thresholds.ts untouched; no new gate.
- global code limits (our code): ≤ 25 logic lines/function, ≤ 80 cols, ≤ 5 params, ≤ 5 locals
  (a destructured name counts as a local). Unexported helpers are allowed and expected; the
  exported names below are final.

## advisor.ts — exported API (names final)
```ts
// lib/memory-feedback/advisor.ts: advisor usage read from Claude Code
// transcripts (Run C, LRN-295): served calls and input tokens per caller
// and model, deduped by message.id, for the FEEDBACK.md section.
export type Use = { caller: string; model: string; calls: number; input: number }
export type Tally = { uses: Use[]; unparsed: number; files: number }
export type Source = { file: string; caller: string }
export const MAIN = 'main loop'
export const UNKNOWN_AGENT = 'sub-agent (unknown)'
export const RETENTION_DAYS = 7
export function transcriptsOf(projects: string, from: number): Source[]
export function callerOf(jsonl: string): string
export function advisorUsage(projects: string, from: number, to: number): Tally
export function compact(n: number): string
export function renderAdvisor(t: Tally, from: number, to: number): string
export function advisorSection(projects: string, from: number, to: number): string
```
Suggested private split (names free): a directory lister that never throws, a per-file line
reader that returns the counted records, a tally step for one record, the sort comparator.

Behaviour:
- `transcriptsOf`: every directory read is wrapped (`readdirSync`/`lstatSync` in a try; an
  unreadable or vanished directory or file is skipped, never thrown). `projects` missing → `[]`.
  For each entry of `projects` that is a real directory (`lstat`, symlinks skipped): every
  regular `*.jsonl` file directly inside → caller `MAIN`; for each real sub-directory `<session>`,
  its `subagents` entry when it is a real directory (lstat), every regular `agent-*.jsonl` inside
  → caller `callerOf(file)`. A file whose `mtimeMs <= from` is skipped (a small saving: it can
  hold no row in the window; the substring pre-filter below is what keeps the scan cheap).
- `callerOf`: lstats the sibling `<name without .jsonl>.meta.json` first: not a regular file
  (symlink, FIFO, dir) or larger than 64 KiB → `UNKNOWN_AGENT`; else reads it; its `agentType` when a string
  matching `/^[A-Za-z0-9_.:-]{1,64}$/`, else `UNKNOWN_AGENT` (missing file, unparsable JSON,
  non-object, bad type: never throws).
- `advisorUsage`: one `seen: Set<string>` of message ids across all files, one tally
  `Map<string, Use>` keyed `caller + '\t' + model`, one `unparsed` counter, `files` = the number
  of sources `transcriptsOf` returned. Per source file
  (read in a try: an unreadable file is skipped): split lines; a line is parsed only when it
  contains `advisor_message` (pre-filter); JSON errors and non-objects skipped. A record is
  considered when `type === 'assistant'`, `Date.parse(timestamp)` is in `(from, to]`, and
  `message.id` is a non-empty string not yet in `seen` (then added). For each element of
  `message.usage.iterations` (array, else none) with `type === 'advisor_message'`: model = its
  `model` when a string matching `/^[A-Za-z0-9._:-]{1,80}$/`, else `'unknown'`; calls += 1;
  input += `input_tokens` when a non-negative safe integer, else 0. A considered record whose
  `JSON.stringify(message.usage ?? null)` contains `advisor_message` but which yielded no call
  → `unparsed += 1` (shape drift; text that merely mentions the word is not in `usage`).
  `uses` sorted: `MAIN` first, then calls descending, then caller, then model ascending.
- `compact(n)`: `n < 1000` → `String(n)`; `n < 999950` → `(n / 1e3).toFixed(1) + 'k'`; else
  `(n / 1e6).toFixed(1) + 'M'` (so `999950` prints `1.0M`, never `1000.0k`).
- `renderAdvisor(t, from, to)`: lines, joined with `\n`, ending with `\n`:
  1. `## Advisor usage (<from> → <to>)`, `<from>` = `all on disk` when `from === 0`, else the
     UTC day `YYYY-MM-DD` (`new Date(ms).toISOString().slice(0, 10)`, as metrics.ts `day`);
     `<to>` = that day of `to`.
  2. blank line.
  3. only when `from > 0` and `to - from > RETENTION_DAYS * 86400000`: the line
     `Transcripts kept 7 d: calls before <day(to - 7 d)> may be missing.` then a blank line.
  4. body: when `t.uses` is empty: `t.files === 0` → `No transcript modified since <from>
     under the projects dir: check the path.` (`<from>` as in the heading); else `t.unparsed > 0`
     → the drift line `<t.unparsed> transcript lines mention advisor_message, none parsed: check
     the transcript shape.`; else `No advisor call in the window.`. Otherwise the table,
     followed (blank line between) by the same drift line when `t.unparsed > 0`:
     ```
     | caller | model | calls | input tok |
     |---|---|---|---|
     | main loop | claude-fable-5-2 | 14 | 3.4M |
     | total | | 41 | 5.1M |
     ```
     (`input tok` via `compact`; the total row sums calls and input).
- `advisorSection(projects, from, to)`: first normalises `from` (outside the try, pure
  arithmetic): a finite number in `[0, to]`, else `0` (state.json is hand-editable: `1e999`,
  `1e17` or `NaN` must not reach `toISOString`). Then `renderAdvisor(advisorUsage(projects, f,
  to), f, to)` in a try; on any throw returns `## Advisor usage (<from> → <to>)` (same dates), a blank
  line and `Unavailable: transcripts unreadable.` (fixed text: an error message could carry a
  path), ending with `\n`. Never throws.

## reader.ts
`commit()` gains no local (it has 5: `fresh, m, v, next, feedback`): the section call reads the
old `lastRun` inline, before any write:
```ts
  const feedback = renderFeedback(m, v, now) + '\n' +
    advisorSection(p.projects, readState(stateOf(p)).lastRun, now)
```
(import `advisorSection` from `./advisor.ts`). The order stays as today: the scan runs while
`feedback` is built, before `appendRows`/`writeState`/`writeSafe`; a throw inside is caught by
`advisorSection`; a kill during the scan leaves nothing written, so a rerun is clean. The
section goes into FEEDBACK.md and the printed output (NEW lines still follow it).

## Tests
advisor.test.ts (bun:test, fixtures in `fs.mkdtempSync(path.join(os.tmpdir(), 'mf-adv-'))`,
removed in afterAll, like reader.test.ts):
1. main transcript: two assistant rows sharing one `message.id`, one advisor iteration
   (model claude-fable-5-2, input_tokens 1500) → one `main loop` row, calls 1, input 1500.
2. a row outside the window (timestamp ≤ from) and one after `to` → not counted.
3. a `user` record and a torn line, both containing `advisor_message` → ignored.
4. one message with two advisor iterations → calls 2.
5. iteration without `model` → model `unknown`.
6. sub-agent `agent-a1.jsonl` + meta `{"agentType":"verifier"}` → caller `verifier`;
   `agent-a2.jsonl` without meta and `agent-a3.jsonl` with `agentType: "../x"` →
   `sub-agent (unknown)`.
7. a transcript whose mtime ≤ from (`fs.utimesSync`) → skipped even with in-window rows.
8. missing projects dir → `{ uses: [], unparsed: 0, files: 0 }`; `advisorSection` on it →
   heading + the `No transcript modified since … check the path.` line; a projects dir with one
   in-window transcript holding no advisor row → `No advisor call in the window.`
9. render: `from 0` → `all on disk`; `compact` 999 → `999`, 1500 → `1.5k`, 999950 → `1.0M`,
   2500000 → `2.5M`; total row sums calls and input; sort order (main loop first, then calls
   desc).
10. the rendered section never contains the fixture's project slug or its path.
11. a message with a `server_tool_use` block named `advisor` and no `advisor_message` iteration
    (and no usage mention) → 0 calls, `unparsed` 0.
12. shape drift: an in-window assistant record whose `usage` holds `advisor_message` in a shape
    the reader does not parse (e.g. `usage.advisor_message: {...}` with no `iterations`) →
    `unparsed` 1, and the render prints the `none parsed` line instead of the plain zero.
13. retention: `from = to - 10 d` → the `Transcripts kept 7 d: calls before <day> may be
    missing.` line; `from = to - 3 d` and `from = 0` → no such line.
14. an unreadable sub-directory (`chmod 000` on a fixture dir, mode restored in a try/finally
    inside the test itself; skip the assertion when running as root) → still returns the other
    files' calls, no throw.
15. `advisorSection` with `from = Infinity`, `from = 1e17` and `from = NaN` → heading `all on
    disk`, never throws.
16. drift under a table: one parsed call plus one drift record → the table, then the drift line.
17. `callerOf` with a meta that is a symlink (to a valid meta elsewhere) → `sub-agent (unknown)`.
reader.test.ts: the existing apply test (or one new apply test on the same fixture) asserts the
output and FEEDBACK.md contain `## Advisor usage`.

## Edge cases
- `from` = state.lastRun = 0 on a first run → everything still on disk, heading `all on disk`.
- Huge files (largest 63 MB, 1.1 GB total): substring pre-filter before `JSON.parse`.
- A message id seen in two files (never seen in the probe) counts once.

RISK: low — read-only reporting added after the existing FEEDBACK body; the labelling path and
its write order are unchanged.
