# Fix plan — stuck poll loops keep sub-agents "waiting on 1 shell"

## Diagnosis
BUG: sub-agents (feater, general-purpose, bugfixer) stay listed in the
agents/tasks panel "waiting on 1 shell" for days, across projects.
ROOT CAUSE: the agent ends its turn with a background Bash poll loop
`until <cond>; do sleep N; done` that never exits; the harness keeps the
agent alive while it owns a running shell.
- (1) 8 of 10 loops: `! pgrep -f "<pat>"` in the exit condition. The Bash
  tool runs the command as `bash -c '<command text>'`, so the shell's own
  argv holds `<pat>`: pgrep -f always matches the loop itself, the
  condition stays false forever. Same mechanism makes `pkill -f <pat>`
  signal its own shell.
- (2) 2 of 10 (game): exit on a guessed output pattern (`grep -q '^done'`)
  while the file holds `\e[0mdone` (ANSI prefix): never matches.
- Both: no time bound, and no need: the harness notifies the agent when a
  background command exits (Bash `run_in_background`), and Monitor exists
  for condition waits.
EVIDENCE: live process trees under 3 claude sessions (until/sleep shells
since 2026-11-26, start times = the panel's "since" times to the minute);
`bash -c 'pgrep -f "zq-uniq-marker-81723" && echo SELF'` prints SELF with no
other process holding the marker; game task output file = `\e[0mdone`.
Not explained by this: the user's third example (bugfixer "11m 11s", no
"waiting on 1 shell") — the game session had live upstream.py/client3.py
children, likely just running.
BLAST RADIUS: any agent, any project, Bash tool; Monitor commands can carry
the same pgrep -f self-match. Repo grep (skills, agents, lib, rules, hooks,
CLAUDE.global.md, skills-external): no command-text `pgrep -f`/`pkill -f`
nor until/while-sleep loop in our doctrine; skills-external/gstack uses
`pgrep -f`/`pkill -f` only inside script files (bin/chrome-cdp) the hook
never sees. skills-external/higgsfield-* references teach multi-line
unbounded `while :; do … sleep N; done` polls: refused once (accepted FP). Live wiring: ~/.claude/settings.json and
~/.claude/hooks are symlinks into this repo: the hook is live in every
session as soon as settings.json is edited.
RELATED MEMORY: LRN-315 (pgrep chained with `;` gates nothing: other
failure); BLK-021 (dead session probe filled /tmp: same family of residue,
other cause). No prior names this cause.

## Facts settled after challenge (2026-11-27)
- Transcripts: the stuck loops were FOREGROUND Bash calls (no
  run_in_background, timeout 600000/400000); at timeout the harness moved
  them to background without killing them. So foreground is NOT bounded:
  R2 covers every Bash call, not only background ones.
- `pgrep -A -f pat` excludes its own shell but still matches a SIBLING
  shell holding the same pattern (tested): faunosteo's 4 concurrent loops
  kept each other alive. `-A` is no remedy; R1 has no `-A` exemption.
- settings.json autoMode hard_deny "Routing around a guardrail": "A refusal
  ends the attempt: report the exact command and the rule that stopped it,
  then wait for the user." A poll-guard deny therefore stops the agent.
- `rtk rewrite` returns rc 3/0 on some loop commands: an updatedInput
  rewrite by poll-guard could race rtk-rewrite's own. Rewriting rejected.

## Fix plan (final, reopened by user 2026-11-27 after confirmation pass)

Scope: every Bash call (foreground or background) and every Monitor call.
Prose is held off by a strict LOOP predicate (real loop syntax), not by
tool mode.

1. NEW `hooks/poll-guard.sh` — PreToolUse, matcher `Bash|Monitor`. Deny
   shape of `hooks/extract-guard.sh` (JSON `hookSpecificOutput`
   `permissionDecision: deny`, reason prefixed `poll-guard:`, exit 0),
   silent when allowed. jq or grep missing → one stderr warning, allow;
   grep rc > 1 → warning, allow. bash 3.2 safe, POSIX ERE only, every path
   ends `exit 0`. `.tool_name` absent → treated as Bash.
   - LOOP: the text holds a word `until` or `while`, a word `sleep`, a `do`
     keyword right after `;` or a newline, and a word `done` (quotes
     included: `bash -c 'until …; do …; done'` counts).
   - R2 (Bash, LOOP, unless BOUNDED). BOUNDED, either:
     a. a SECONDS comparison: `SECONDS`, optionally preceded by `$`, `${`
        or `"$`, optionally followed by `}` and/or `"`, then spaces, then
        one of `-ge -gt -le -lt >= <= > <` (covers `[ $SECONDS -ge N ]`,
        `[ "$SECONDS" -lt N ]`, `${SECONDS}`, `(( SECONDS < N ))`);
     b. the command STARTS with `timeout` or `gtimeout`, then any option
        words (`-k N`, `-s SIG`, `--foreground`, `--kill-after=N`,
        `--signal=SIG`, `-v`), then a duration whose number is ≥ 1 (a
        `timeout` on the probe inside the loop does not count; `timeout 0`
        does not count).
     Reason: "poll-guard: poll loop with no time bound: if its condition
     never comes true, the shell outlives the tool timeout and the agent
     stays 'waiting on 1 shell' for days. Bound it inside the loop:
     `until <cond> || [ $SECONDS -ge 1800 ]; do sleep 5; done` (in a
     quoted inner script, single-quote it so $SECONDS is not expanded
     early), or wait for the completion notification of the command you
     are waiting on."
   - R1 (Monitor commands, and Bash commands matching LOOP): a `pgrep` or
     `pkill` word followed, in the same segment (up to `;` `&&` `||` `|`
     `&` newline), by an option cluster holding `f` (`-f`, `-fa`, `-lf`,
     `-9f`, `-xf`, `-Af`) or `--full` → deny, every OS, no exemption
     (`-A` still matches sibling loops). Reason: "poll-guard: pgrep -f
     matches every shell whose command line holds the pattern: this one
     and any sibling loop, so the condition never changes. Wait on the
     job's own end instead: its completion notification, or an exit
     marker it writes (`cmd >out 2>&1; echo \"rc=$?\" >>out`, then `until
     grep -q '^rc=' out || [ $SECONDS -ge 1800 ]; do sleep 5; done`)."
   - Both fire → ONE deny whose reason carries R1's text then R2's.
   - Monitor gets no R2: its schema has `timeout_ms` (default 5 min,
     capped at 30 min) and no persistent flag (tool schema read
     2026-11-27; older transcripts show a `persistent` field, gone).
2. NEW `lib/tests/poll-guard.test.sh` (style of extract-guard.test.sh;
   `run <tool> <bg:true|false|absent> <cmd>`):
   R2 deny, each in fg AND bg: the observed shapes reduced (`until [ -s f ]
   && ! grep -q x f; do sleep 5; done`, `S=/x; until grep -q y $S/f; do
   sleep 10; done; tail f`, `cd /p; until grep -qE "a|b" f; do sleep 5;
   done`, game `until grep -q '^done' f; do sleep 5; done`); `until timeout
   3 nc -z h 5432; do sleep 1; done`; `timeout 0 bash -c 'until x; do sleep
   1; done'`; `bash -c 'while true; do sleep 1; done'`; multi-line
   `while :; do\n  st=$(curl x)\n  sleep 12\ndone`.
   R2 allow (fg and bg): `until grep -q R l || [ $SECONDS -ge 600 ]; do
   sleep 1; done`; `[ "$SECONDS" -lt 600 ]` in a while; `${SECONDS}`;
   `(( SECONDS < 60 ))`; `timeout 600 bash -c 'until x; do sleep 5; done'`;
   `timeout -k 5 600 bash -c '…'`; `gtimeout --foreground 10m sh -c '…'`;
   `npm run dev`; `cargo test`; `sleep 2`; `for i in 1 2 3; do sleep 1;
   done`; `git commit -m "fix(hooks): poll-guard (pgrep -f; until … sleep)"`;
   `grep -rnE 'pgrep -f|pkill -f' .`.
   R1 deny: Monitor `until ! pgrep -f "x y"; do sleep 1; done`; Monitor
   `pkill -9 -f x`; Monitor `pgrep -A -f x`; Monitor `pgrep
   --ignore-ancestors -f x`; Monitor `pgrep -xf "a b"`; Bash `until ! pgrep
   -fa x || [ $SECONDS -ge 60 ]; do sleep 1; done` (bounded: R1 alone).
   R1 allow: Monitor `pgrep -x cargo`; Monitor `pgrep -x a & tail -f log`.
   Both: `until ! pgrep -f run-all.sh; do sleep 3; done` → one deny, reason

ACCEPTED FALSE POSITIVES (one test each): prose holding a full loop with
pgrep -f passed as an argument (`--body "…; do …; done"`): use a body file;
the higgsfield-style unbounded `while :` polls: refused once, rewrite with

MISSES: loop in a script file (`bash poll.sh`); a loop built by variable;
`tail -f f | grep -q x` (no loop: hangs on cause (2) too); `$SECONDS` inside
a double-quoted inner script (expanded early by the outer shell; the
reason tells to single-quote); a standalone `pkill -f` outside any loop.
MINOR dropped: `[p]attern` trick (literal can appear in the wrapper argv);
`pgrep -x <name>` as a remedy (interpreter-run scripts have comm `bash`).

RISK: medium-low. Every Bash call is read; prose without loop syntax
passes. A refusal stops the agent until the user's hard_deny exception
lands, then the agent corrects and retries.
MINOR dropped: quadratic `${cmd%%$'\n'*}` on a first line of several hundred KB (8 s at 500 KB, security gate LOW): no real command is that long.
