## Router facts that bind the plan
- Rows are phase names; a phase names a tier; a tier is an ordered alias list, first alias not down is used (`best` = fable > opus > sonnet). An agent gets its row's model at spawn, upward only within the tier; explicit `model=` at a call site wins (BDR-115, BDR-077). No dispatch of verifier / security-auditor carries an explicit `model=` (grep 2026-10-21: tour, onboard, audit-delta dispatch them bare).
- `lib/tests/effort-routing.test.sh` locks: every routing.json phase equals the code copy in `register.ts` DEFAULT_CONFIG (`code_phase`); every rowed agent's frontmatter `model:` equals its phase's tier head and `effort:` equals the phase effort, unless a `changed` entry explains the drift (WARN). Neither verifier nor security-auditor has a `changed` entry, so the frontmatter MUST move with the row or the census FAILs.
- `lib/tests/model-routing.test.sh:23-24` greps the literal old pins.
- `register.test.ts` builds every world from `baseRouting()` (11 phases, :65-78). `logMissingPhases` (register.ts:862-869) diffs `DEFAULT_CONFIG.phases` against the file, so a DEFAULT_CONFIG phase absent from the fixture is logged in every test: :1592-1601 expects exactly `lacks phases reflect`, and `/route pending` counts `st.cfg.phases` (:2555 `pending confirmation: 19`, :2567 `17`). The fixture gains `audit` and the two counts become 20 and 18.
- `inTier` (register.ts:3163-3174) writes a model only when it is the tier head or ranks above it; otherwise "tier … down, frontmatter model kept" and the frontmatter runs (test :1278-1291). A best-tier row with a `fable` frontmatter therefore has NO fallback: every Fable credit outage (BLK-030/031) would spawn both gates on a dead model. Decision (user 2026-10-21): the gates keep `model: opus` as the outage floor; the router lifts them to Fable when it is up; Fable down or router off = opus. The census gets a named carve-out: a best-tier agent row's model floor is the tier's SECOND alias.
- No stash. `~/.claude/settings.json` and `~/.claude/skills/model-router` are symlinks into the repo: stashing settings.json puts every new session back on Fable 1M (the BLK-032 condition) and stashing routing.json re-arms the router's dialogs. The dirty copies carry over the branch start unchanged (`git diff develop..HEAD` is empty for both files). They are committed FIRST on the feature branch as one dedicated commit (the router's own dialog writes: `deploy` apply→verify + `changed` entry, `release-executor` Keep; the session model `opus` = BLK-032 policy point 1), before the executor runs. Feat B then carries CLAUDE.global.md, the BDR and the docs only.
- `confirmed.agents` records first-use dialog answers; an unconfirmed row re-opens the dialog at first use. This feat is the user's decision → set `audit` by hand for both.
